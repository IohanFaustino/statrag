Extension mode topology-C deepagents

Produces a structured chapter digest: curated section text with augmented footnotes drawn from the wider corpus and Wikipedia. All augmentation lives in footnotes — curated_text is never modified.

What it serves

Use when you want to read a whole chapter as a clean, enriched document — key concepts preserved with their formal definitions and notation, gaps filled with cross-book comparisons, missing derivations, and worked examples as footnotes. Not for a single question (use Tutor / Q&A) or a linear walkthrough (use Facilitate / Resume).

Retrieval & text processing

FeatureDetail
Corpus retrievalHybrid dense+sparse (hybrid_search), top_k=10, excluding base book. Cross-round dedup via seen_ids set shared between runner and tool closure.
Wikipedia lookupDirect title summary → disambiguation fallback via /w/api.php?action=query&list=search on 404. Timeout 10 s.
Subtopic filteringExact/substring match on h2_path + section_id → hybrid_search embedding fallback → whole chapter fallback.
Math normalizer_normalize_math_delimiters: \(...\) → $...$, \[...\] → $$...$$. Applied after _isolate_midline_display.
Footnote marker cleaner_strip_md_footnote_markers: removes [^n] from curated_text (React renders them literally).

Output schema

ExtensionDigest
  book: str
  chapter: str
  points: list[ExtensionPoint]
    title: str
    curated_text: str          ← source text only, no augmentation
    footnotes: list[ExtensionFootnote]
      marker: str              ← "a", "b", "1", "2" …
      body: str                ← ≥ 40 words, KaTeX-ready ($…$ / $$…$$)
      source: str              ← book slug + §section, or Wikipedia URL
      kind: "corpus" | "wikipedia"
  unfilled_gaps: list[str]     ← queries where no source scored ≥ 3

Invariant #14: all augmentation lives in footnotes[].body. curated_text is never modified. Invariant #38: non-trivial points should have ≥ 2 footnotes (orchestrator enforces via re-delegation, not schema).
