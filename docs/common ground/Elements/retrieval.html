Hybrid retrieval pipeline

The chat service performs multi-stage retrieval entirely in-process. Dense embeddings (OpenAI text-embedding-3-large) and sparse BM25 vectors are prefetched in parallel, then fused by Qdrant-native Reciprocal Rank Fusion (RRF, k=60). The fused pool feeds a concept-density selector that expands the top sections, runs cross-encoder reranking, and applies an author-diversity round-robin before handing sources to the drafting stage.

flowchart TD Q["Query"] --> EXP["Query expansion (HyDE / multi-query / decompose)"] EXP --> D["Dense — text-embedding-3-large"] EXP --> S["Sparse — BM25 (fastembed Qdrant/bm25)"] D --> RRF["Qdrant RRF fusion (k=60)"] S --> RRF RRF --> DEN["Concept-density select (score = 0.6·concept_count_norm + 0.4·rrf_norm)"] DEN --> SEC["Section-chunk expand (scroll all chunks of top_sections=4)"] SEC --> ADJ["Sibling-section expansion (page-band ±25, rerank-gated)"] ADJ --> RR["Cross-encoder rerank (BAAI/bge-reranker-v2-m3, top_n=10)"] RR --> DIV["Author-diversity round-robin (_DIVERSITY_MAX=6, target auto)"] DIV --> OUT["Selected sources (final_top_n=8)"]

Image retrieval path

Images live in separate <field>_images collections (named by replacing _textbooks with _images in the text collection name). The image path is dense-only — no BM25 — because captions are embedded as text at ingest time using text-embedding-3-large.
