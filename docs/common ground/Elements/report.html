2 · The "modal is the same" cause (runtime, not code)

Two dev Vite servers were running (:5175 pid 201184 + :5176 pid 398277) from repeated ./scripts/dev.sh runs, plus a 19h-old prod Docker on :5173. HMR for the data-only tutorPipeline.ts change hadn't propagated to the tab you had open.
Fix: killed the duplicate dev processes, started one clean server (:5175 + :8766), hard-reloaded. The modal then correctly showed Planner and no Critique.

3 · Real bug found by service monitoring

Symptom (dev log): every tutor request logged:
build_synthesis_plan failed; proceeding without a plan
openai.BadRequestError: 400 - Invalid schema for response_format 'SynthesisPlan':
  ... Extra required key 'outline' supplied.

Root cause: SynthesisPlan.outline: dict[str,str] — OpenAI strict structured outputs forbid open-keyed objects. build_synthesis_plan 400'd, caught the error, returned None → no plan injected, orchestrator fell back to the per-author split instead of LLM-chosen tasks. It failed gracefully, so the answer still streamed and the bug stayed hidden. After removing the dict it then truncated (LengthFinishReasonError, 850-token cap).

Fix: slimmed SynthesisPlan to exactly {thesis, contrasts, tasks} (removed the carried-over outline+ledger and their classes), trimmed the prompt, raised the cap to 1200. Added a regression guard test that rejects any open-keyed dict in a response_format model.

Proof — live API call (4 sources):
