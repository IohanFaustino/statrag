Pipeline

Six stages executed by src/ingestion/pipeline.py via run_chapter(). Each stage is labelled A–F in the module docstring (line 3–9).

flowchart TD SRC["Source .md per book/chapter"] --> RGX["B · Regex pass — normalize structure<br/>(regex_pass.py)"] RGX --> ENR["C · LLM enrich — synopsis + index_extended<br/>DeepSeek v4-flash default, non-thinking<br/>(llm_enrich.py)"] ENR --> BLD["D · build_documents — 1 section = 1 chunk<br/>split at 8000 tok · tiktoken cl100k_base<br/>(build_documents.py)"] BLD --> EMB["E · Dense embed — text-embedding-3-large (OpenAI)<br/>+ BM25 sparse (fastembed Qdrant/bm25)"] BLD --> CAP["E · Image caption embed<br/>OpenAI text-embedding-3-large on caption text"] EMB --> UP["E · Qdrant upsert — field_textbooks"] CAP --> UPI["E · Qdrant upsert — field_images"] UP --> REG["F · Manifest register — data/parsed/manifest.json"] UPI --> REG

Note: there is no separate "Preprocess" stage inside pipeline.py — preprocessing (e.g. kobo_preproc.py) is a one-time offline step that produces *_fixed.md before ingestion. The pipeline reads the already-preprocessed source directly. Stage A (static yaml + book.json) is handled outside run_chapter().

Providers

Three distinct provider roles in the pipeline. --provider controls only enrichment; embeddings and captioning are always OpenAI.

RoleProviderModelConfig key / env varSource
LLM enrichment (synopsis + index_extended) DeepSeek (default) or OpenAI deepseek-v4-flash (non-thinking, thinking disabled via extra_body) RAG_INGEST_DEEPSEEK_MODEL / RAG_DEFAULT_PROVIDER=deepseek src/core/config.py:49,68 · src/ingestion/llm_client.py:36-42
Dense embeddings (text chunks) OpenAI text-embedding-3-large (3072d) EMBEDDING_MODEL src/core/config.py:38 · src/ingestion/pipeline.py:95
Image caption embedding OpenAI text-embedding-3-large (caption text embedded, not vision) EMBEDDING_MODEL src/ingestion/pipeline.py:134-136
Sparse (BM25) fastembed (local) Qdrant/bm25 _SPARSE_MODEL constant src/ingestion/pipeline.py:53

Thinking is explicitly disabled for DeepSeek enrichment: v4 model IDs default to thinking mode which produces empty content and breaks JsonOutputParser. See src/ingestion/llm_client.py:33-42.

Commands

Ingest a chapter

python -m src.ingestion.pipeline \
    --book <slug> \
    --chapter ch01 \
    [--provider deepseek|openai] \
    [--force] \
    [--limit-sections N]

--force bypasses the manifest skip check (pipeline.py:186-190). --limit-sections N keeps only the first N sections and skips the manifest write — useful for cost-controlled preview (pipeline.py:198-200, 240).

Show ingest status

python -m src.ingestion.pipeline --status

Reads data/parsed/manifest.json and prints book / chapter / chunks / provider / timestamp for each ingested chapter (pipeline.py:261-268).

Image-only ingest (VLM / EPUB markdown)

python -m src.ingestion.ingest_images_only \
    --book <slug> \
    --md "/abs/path/to/vlm/book.md" \
    [--format vlm|epub|auto] \
    [--dry-run]

Skips text-side entirely; reads image refs + captions from VLM or EPUB-converted markdown; embeds caption text; upserts to <field>_images. Idempotent (UUID5 IDs). (src/ingestion/ingest_images_only.py:290-304).

Preprocessor (one-time, offline)

python -m src.ingestion.processed.kobo_preproc \
    --src "/abs/path/to/input.md" \
    --slug <slug>

Converts Packt/kobo EPUB-HTML pandoc exports (span-wrapped text, .pagebreak divs) into clean markdown. Runs pandoc + kobo_filter.lua, then post-processes header merging and blank-line collapsing. Output: src/ingestion/processed/<slug>_fixed.md — point the book yaml source_path here.

Chunking & payload

Chunk rule

  • 1 section = 1 chunk (no parent/child split). Source: src/ingestion/build_documents.py:3-5.
  • If a section exceeds 8000 tokens (TARGET_TOKENS = 8000, build_documents.py:29), it is split into N windows of 8000 tokens with 200-token overlap (OVERLAP_TOKENS = 200, build_documents.py:30).
  • Hard safety cap: 8190 tokens (HARD_MAX_TOKENS = 8190) — one below the OpenAI embedding limit of 8191. Oversize chunks are logged as errors (build_documents.py:31).
  • Token counter: tiktoken encoding cl100k_base (build_documents.py:28). Matches the text-embedding-3-large / GPT-4 family tokenizer.
