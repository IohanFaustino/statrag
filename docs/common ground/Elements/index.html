1 · What orchestrator-workers means

"A central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results. The key difference from simple parallelization is its flexibility — subtasks aren't pre-defined, but determined by the orchestrator." — Anthropic, Building Effective Agents

Three roles: Orchestrator (LLM) decides the subtasks dynamically · Workers (LLMs, parallel) each solve one · Synthesizer (LLM) integrates. The defining trait is the orchestrator choosing the decomposition; a fixed split is a different pattern (parallelization / sectioning).

4 · What closes the gap

Promote the decomposition from a code rule to a real orchestrator LLM step:

  • orchestrate(question, sources) → list[WorkerTask{focus, source_ranks}] — an LLM that decides, per question, how many workers and what each covers (per author, per sub-topic, or merging thin authors).
  • Delegate the chosen tasks → existing parallel workers → existing synthesizer.
  • Keep the current per-author grouping as the fallback when the orchestrator declines to decompose.
  • Surface it on the same selectable Drafting workflow node.

13 · Detached, resumable streaming — runs survive conversation-switch ✓ implemented (2026-05-22)

Symptom: send a query, the answer is mid-stream, switch to another conversation → the stream dies and the answer is lost entirely (never persisted).

Root cause (two layers). (1) Frontend holds one useChat reducer = one conversation in memory; switching calls loadConversation → abortRef.current.abort() (kills the fetch) and replaces state. (2) Backend chat_event_gen is driven by the SSE connection; the client abort makes sse-starlette see a disconnect and cancel the generator task — generation stops, and the assistant row is only persisted after the generator completes (api.py:167), so the partial answer vanishes.

Fix: detach generation from the connection and make the stream replayable by sequence number. Generation runs as a server-side task writing to a per-conversation event buffer; the HTTP connection is just a subscriber. Disconnect (switch / refresh / tab-close / network drop) no longer cancels generation; reconnecting replays missed events.
