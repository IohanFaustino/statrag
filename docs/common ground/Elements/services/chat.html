Chat Service · user-facing

The SSE-streaming conversational layer: a FastAPI app exposing four chat modes over hybrid retrieval, including the deep-tutor pipeline (query planning → density retrieval → coverage → orchestrator-workers → vision/formula-recovery → structured DeepTutorAnswer).

Request → SSE

The chat service exposes POST /api/chat as the primary entry point. When a conversationId is present the turn runs as a detached, resumable run (§13): generation and persistence complete even if the client disconnects, and the stream can be replayed via GET /api/chat/{id}/stream?after=N. Without a conversationId the legacy connection-bound, ephemeral path is used.

sequenceDiagram participant B as Browser participant A as api.py (POST /api/chat) participant R as router.py (stream_chat) participant D as _V2_DISPATCH (mode runner) participant AG as Agent runner participant RTV as Retrieval + LLM participant B2 as Browser (EventSource) B->>A: POST /api/chat {message, mode, model, conversationId, …} A->>A: runs.start_run(conv_id, chat_event_gen) A->>R: stream_chat(req, history) R->>D: dispatch by req.mode (tutor/qa/facilitate/resume) D->>AG: run_deep_tutor / run_qa / run_chapter / run_facilitate AG->>RTV: hybrid retrieval + coverage + workers + LLM draft RTV-->>AG: sources, drafts, figures AG-->>A: yield events (meta, token, structured_output, sources_full, …) A-->>B2: SSE stream framed as {event, id, data}

SSE event types emitted (exact strings from api.py line 257 docstring + event-loop body lines 186–215): meta, token, paragraph_break, math_block, source_chip, sources_full, figures_full, figures_meta, retrieval_meta, usage, done — or error + done on failure. The special structured_output event (emitted by agents that return a typed Pydantic payload, e.g. TutorAnswer / QAAnswer) is also intercepted by chat_event_gen for persistence. Every event carries a monotonic seq field (used as the SSE id: frame).

Sub-packages

The chat service is organized into nine sub-packages / sibling modules. api.py is the FastAPI entry point; router.py dispatches to per-mode runners; each runner lives in agents/. The runners consume retrievers/, llm/, and tools/ as building blocks, while prompts/ and schemas/ supply the text and type contracts.

Deep-tutor pipeline

The deep-tutor pipeline (agents/deep_tutor.py::run_deep_tutor) is the most complex path in the service. It runs when req.mode == "tutor" and TUTOR_DEEP_MODE != "0". The canonical pipeline graph and env-var table are documented in docs/services/chat-features/36-deep-tutor.md. The walkthrough below names the stages in execution order.

Stage walkthrough

StageWhat runsKey details
1a. Concept extraction extract_concepts_ex (query planner) Nano LLM call that returns a QueryPlan: additional retrieval queries, grading facets (things the answer must cover), and a recommended diversity_target. Best-effort: failure yields empty plan, falls back to single-query path. Gated TUTOR_MULTI_QUERY.
1b. Wide candidate pull retrieval.hybrid_search (no rerank) Runs in parallel with concept extraction via asyncio.gather. Dense + BM25 RRF across all active per-field Qdrant collections. No cross-encoder yet — the density stage handles that.
2. Density select + expand retrievers/density.py::density_score_candidates Scores each candidate by concept-term frequency (alpha=0.6) + normalized RRF score (0.4). Scrolls the top _TOP_SECTIONS (default 4) sections fully. Optionally appends sibling chunks at near-zero score (rerank-gated). Env: TUTOR_DEEP_TOP_SECTIONS, TUTOR_DENSITY_ALPHA, TUTOR_NEIGHBOR_EXPAND.
2b. Cross-encoder rerank + diversity rerankers.py + retrievers/diversity.py BAAI/bge-reranker-v2-m3 run via asyncio.to_thread. After rerank, author-diversity round-robin ensures up to _DIVERSITY_MAX=6 author groups are represented. Author-aware rerank floor re-inserts the best dropped chunk of any missing author.
3. Coverage check agents/coverage.py::assess_coverage Grades each planner facet against the selected sources. Missing facets trigger a targeted re-query (capped at 1 call). Best-effort: any failure → no change. Gated TUTOR_COVERAGE_CHECK (default on).
4. Image judge retrievers/image_density.py → agents/image_judge.py Fetches image candidates with co-location boost (same book/chapter as top text sources). Two-tier judge: caption-only nano LLM (cheap, parallel) for all candidates; optional vision (gpt-4o-mini) for borderline confidence (default 0.4–0.7). Up to 2 vision calls per query. Approved figures carry aspect_hint for placement. Env: TUTOR_IMAGE_JUDGE_VISION_MAX.
5a. Single draft _stream_draft (single LLM call) Default when tutorWorkflow="single" (or unset). OpenAI-family models use _stream_structured (native response_format=DeepTutorAnswer); non-OpenAI models use _stream_draft_via_router (json_object path + repair). Optional critique loop gated TUTOR_DEEP_CRITIQUE=1 (off by default).
5b. Orchestrator-workers agents/orchestrator_workers.py::run_orchestrator_workers When tutorWorkflow="orchestrator" or "orchestrator-deep". Planner LLM produces a SynthesisPlan (tasks + contrasts); workers run in parallel (one per author); L0 synthesizer integrates briefs into DeepTutorAnswer. Falls back to single draft if fewer than 2 workers succeed.
5c. Formula recovery agents/formula_gaps.py → agents/formula_recovery.py Runs between worker briefs and the L0 synth. detect_formula_gaps is pure/deterministic: finds concepts whose defining equation was OCR-dropped to an image placeholder. recover_formulas tries per gap in parallel: formula_cache lookup → vision off the figure → text re-query. Recovered LaTeX injected into synth as <recovered_equations>. Cached globally in formula_cache Qdrant collection (lookup score ≥ 0.93). Completely best-effort.
6. Finalize _convert_to_tutor_answer + citation helpers Converts DeepTutorAnswer → TutorAnswer (assembles text from aspect fields, packs raw aspects into aspects dict). _reconcile_tutor_citations re-indexes inline [N] markers; _ensure_marker_citations synthesizes any missing citation entries. LaTeX escape repair applied before and after JSON parse (invariant 13).

Per-module deep-dive

agents/

FileRoleKey entry point
deep_tutor.py The deep-tutor pipeline runner. Executes all six stages above: parallel concept extraction + wide retrieval, density select, coverage, image judge, draft (single or OW), finalize. Emits the full SSE event sequence. run_deep_tutor(req: ChatRequest) -> AsyncIterator[dict]
qa.py Punctual Q&A four-node pipeline: scope → retrieve → scoped generate → verify/finalise. Emits QAAnswer via structured_output. Corpus miss yields honest no-coverage message with empty citations, never fabricated. run_qa(req: ChatRequest) -> AsyncIterator[dict]
chapter.py Shared runner for facilitate and resume chapter modes. Pipeline: parse-scope → fetch-chapter → resolve-subtopics → map(per-section) → stitch → ground. Block order equals reading order (page_from), never re-sorted. run_chapter(req: ChatRequest) -> AsyncIterator[dict]
facilitate.py Facilitate-mode concept-map-first teaching pipeline. Per section: build concept map (key points + concepts), sub-retrieve explanations same-author-first, rewrite as key-point blocks with [[cN]] anchors, verify grounding. Emits FacilitateDigest. run_facilitate(req: ChatRequest) -> AsyncIterator[dict]
orchestrator_workers.py Orchestrator-workers drafting workflow. Planner → per-author workers in parallel → formula recovery → L0 structured synthesizer. Groups sources by author from diversity.author_key. Falls back to (None, {}) when fewer than 2 workers succeed, signalling caller to use single draft. run_orchestrator_workers(...) -> tuple[DeepTutorAnswer | None, dict]
coverage.py CRAG-lite coverage check. After retrieval, grades each planner facet (QueryPlan.facets) against the source pool. For unsupported facets, fires a targeted re-query (capped at 1). Best-effort: any failure → no change. Gated TUTOR_COVERAGE_CHECK. assess_coverage(sources, query_plan, client, model) -> list[Source]
image_judge.py Two-tier pertinence judge for image candidates. Tier 1: caption-only nano LLM in parallel (~150ms each). Tier 2: optional vision LLM (gpt-4o-mini) for borderline confidence 0.4–0.7, capped at 2 calls. Returns approved figures (max 3) with aspect_hint and judge_confidence. judge_figures(candidates, query, concepts, ...) -> list[FigureCandidate]
formula_recovery.py Per-gap formula recovery: cache → vision-on-figure → text re-query. Runs all gaps in parallel via asyncio.gather(return_exceptions=True). Returns only equations that were found. Any failure is a cache miss. recover_formulas(gaps, sources, query) -> list[RecoveredEquation]
formula_gaps.py Pure, deterministic detector for concepts whose defining equation is OCR-dropped to an image placeholder. No I/O, no LLM. Identifies definitional spans via regex (_DEF_RE) and checks for missing $$…=…$$ blocks. detect_formula_gaps(sources, query) -> list[GapConcept]
formula_cache.py Global concept → defining-equation Qdrant cache (formula_cache collection). Stores recovered equations as vector points; lookup gates on cosine score ≥ 0.93. Swallows all exceptions (best-effort). Auto-creates collection on first write. cache_lookup(concept) -> str | None, cache_write(concept, latex)
ow_deepagents.py Eval-only harness level 3: deepagents synthesizer agent. Each AuthorBrief is preloaded as a file into a deepagents agent's virtual filesystem; agent synthesizes free-text (no DeepTutorAnswer schema). Requires optional deepagents install. synthesize_with_deepagents(briefs, query, ...) -> str
ow_harness.py Harness-level scaffold for the OW stage (ablation). Selects harness level from TUTOR_OW_HARNESS (0–7). Level 0/1 = production path (L0 structured synth); levels 5–7 = eval-only deepagents variants. Level 4 rejected → falls through to L0. Any harness failure always falls back to L0. select_harness_level() -> int, maybe_traced(fn)
_scope.py Shared book/chapter/section scope resolver for chapter and Q&A modes. Catalog-in-prompt: parse LLM receives a compact book catalog so fuzzy/paraphrased references resolve to a slug with confidence. Numeric section refs expanded deterministically. maybe_clarify gates on book_confidence < 0.6 or ambiguous candidates. resolve_book(req, catalog) -> BookResolution, maybe_clarify(...)

llm/

FileRoleKey detail
router.py Provider routing + model registry. get_llm(model_id) returns (BaseLLM, model_id). aclient_for(model_id) returns a raw AsyncOpenAI client for direct calls. is_structured_output_capable(model_id) is the single source of truth for OpenAI strict json_schema eligibility. Routing rules: deepseek-prefix → DeepSeekChat; Groq set membership → GroqChat; gemini-prefix → GeminiChat; qwen-prefix → QwenChat; else → OpenAIChat. Groq uses set membership (not prefix) to avoid collision with openai/gpt-oss-* IDs.
structured.py Per-model structured-output capability gate. Decides JsonMode.SCHEMA (native json_schema) vs JsonMode.OBJECT (json_object + schema hint in system message). OpenAI and Gemini/Qwen support SCHEMA; DeepSeek and current Groq models support OBJECT only. json_mode_for(model_id) -> JsonMode; used by apply_structured_output for Q&A and chapter mode LLM calls.
base.py Abstract BaseLLM + ChatMessage + LLMError. All concrete clients implement stream(messages, *, model, temperature, max_tokens, response_format) -> AsyncIterator[str]. Common interface consumed by the v1 orchestrator streaming path.
openai_client.py OpenAI-family streaming client. Uses openai.AsyncOpenAI with the official API key. Passes response_format verbatim (supports native json_schema strict mode). Default provider for gpt-5.4-nano-2026-03-17 and all gpt-* IDs. No quirks; full structured-output support.
deepseek_client.py DeepSeek streaming client via OpenAI-compatible API. Quirk (code-confirmed): DeepSeek V4 IDs default to THINKING mode, which burns the output budget on hidden reasoning and returns empty content on the structured draft path. _thinking_extra_body disables thinking via extra_body={"thinking": {"type": "disabled"}} for all models except deepseek-reasoner. Gated by env DEEPSEEK_DISABLE_THINKING (default "1" = disable). response_format is accepted but DeepSeek ignores native json_schema; orchestrator falls back to repair retry (comment on line 58).
gemini_client.py Google Gemini streaming client via OpenAI-compat endpoint. Quirk (code-confirmed): uses strict=False in _build_response_format to avoid schema-feature rejections on the compat layer — comment states "same safety net as DeepSeek". Not structured-output capable via strict json_schema. _build_response_format always sets strict: false.
groq_client.py Groq streaming client via OpenAI-compat API. Chat-only (no ingestion). Routes via set membership (GROQ_MODEL_IDS) to avoid openai/gpt-oss-* prefix collision. Current Groq Llama/gpt-oss models use JsonMode.OBJECT; Groq kimi models use SCHEMA. When draft model is Groq, _maybe_append_groq_addendum appends the Groq-specific prompt rules (invariant 27).
qwen_client.py Alibaba Qwen streaming client via DashScope OpenAI-compat endpoint. Quirk (code-confirmed): uses strict=False in _build_response_format — same rationale as Gemini ("caller falls back to JSON-repair path if DashScope compat layer rejects the schema"). Not structured-output capable via strict json_schema. Memory note: qwen-plus timed out under response_format=json_schema; free-text + parse fallback is the safe path.

retrievers/ + retrieval.py

FileRoleKey entry point
retrieval.py Hybrid retrieval primitive. Dense (text-embedding-3-large) + sparse (BM25 via fastembed) prefetched in parallel, fused by Qdrant RRF (k=60). Iterates all active per-field collections. Also exposes search_figures / search_figures_with_scores for image retrieval. hybrid_search(query, book_filter, top_k, ...) -> list[Source]
retrievers/density.py Concept-density retriever. Two stages: coarse hybrid search + concept-TF scoring (alpha=0.6); section expand + cross-encoder rerank. Optionally adds sibling chunks (same parent, page-band ±25) as low-score pseudo-points before reranking. density_score_candidates(query, concepts, ...) -> list[Source]
retrievers/diversity.py Author-perspective diversity round-robin. Groups section keys by author_key (authors_short → authors → book slug). Round-robin by relevance order; year-spread tiebreak for 2nd+ picks from same author. Author-aware rerank floor re-inserts dropped chunks. diversify_section_keys(scored_keys, key_meta, target_authors, top_sections) -> list
retrievers/image_density.py Image candidate retrieval with co-location boost. Calls search_figures_with_scores then adds co_location_boost=0.15 to figures whose (book, chapter) matches a top text source. Returns pool=6 candidates. fetch_image_candidates(query, text_sources, collections, k=6) -> list[FigureCandidate]

Rationale & invariants

Lockstep rule — a pipeline stage spans six artifact classes

Every stage of the deep-tutor pipeline (concept planner, retrieval, density+rerank, author-diversity, coverage, orchestrator-workers synthesis, vision-explain, formula-recovery) is not one file. Its behavior, its prompt, its request knobs, its diagram node, and its docs are separate artifacts that must stay consistent. Why structured output is enforced (and how)

The deep-tutor draft produces a DeepTutorAnswer — a strongly-typed 6-aspect schema. Invariant 36: strict json_schema structured output is only sent to OpenAI-family models; all other providers (deepseek, qwen, gemini, groq) go through the json_object path with a schema hint appended to the system message. The predicate is_structured_output_capable(model_id) in llm/router.py is the single source of truth and mirrors the provider dispatch exactly.

Invariant 23: schema-level equation enforcement — every ### subsection of a mathematical definition must carry a real $$…$$ defining equation. Word-form pseudo-equations like $$\text{Squared bias}+\text{Variance}$$ are rejected by DeepTutorAnswer._require_component_equations at validation time; the ValidationError rides the ADR-005 repair path to backfill. Best-effort: the check is skipped under context={"skip_format_checks": True} for the final fallback so a structurally-valid-but-format-imperfect answer renders rather than blanking the turn.

Key invariants (from docs/system/invariants.md)

  • Invariant 13 — Every raw model JSON in deep_tutor.py must be pre-processed by _repair_latex_escapes before json.loads. Every aspect string must be post-processed by _repair_latex_post after parse. OpenAI structured-stream silently corrupts single-backslash LaTeX commands (\theta → tab + heta).
  • Invariant 14 — figures_full SSE event is emitted on EVERY tutor turn (even with empty figures: []). Frontend can rely on event arrival to distinguish "no figures" from "image branch never ran".
  • Invariant 25 — Detached, resumable runs (§13): a POST /api/chat with a conversationId runs as a background asyncio.Task whose generation and persistence complete even with zero subscribers (client disconnect ≠ cancel). Every SSE event carries a strictly increasing 1-based seq. At most one active run per conversation.
  • Invariant 28 (Zeroth law) — Every system prompt in src/services/chat/ must be XML-tagged with at minimum <role> + <context> + <task>. Plain-text "you are X" prompts are forbidden — they silently break smaller models.
  • Invariant 33 — The query planner always returns a QueryPlan and never raises to its caller. Failure degrades: chain → single-call → keyword heuristic.
  • Invariant 35 — Deep-synthesis live path = L0 structured synth (no schema-fill). The live orchestrator-deep path routes directly to the L0 structured synthesizer (_stream_structured) — no _schema_fill re-express pass. deepagents+skill (L5) and structured deepagents agents (L6/7) are eval-only.
  • Invariant 37 — Formula recovery is gap-triggered + best-effort. The stage never changes a normal answer and never raises to its caller. Recovered LaTeX is injected as <recovered_equations> and used verbatim by the synthesizer. Any failure anywhere → empty block → today's behavior.
