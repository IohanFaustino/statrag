Hybrid dense + sparse BM25 retrieval over per-field Qdrant collections, fused by Reciprocal Rank Fusion (RRF k=60), cross-encoder reranked, and author-diversity round-robined — the retrieval primitive every chat mode builds on.

Hybrid retrieval pipeline

The chat service performs multi-stage retrieval entirely in-process. Dense embeddings (OpenAI text-embedding-3-large) and sparse BM25 vectors are prefetched in parallel, then fused by Qdrant-native Reciprocal Rank Fusion (RRF, k=60). The fused pool feeds a concept-density selector that expands the top sections, runs cross-encoder reranking, and applies an author-diversity round-robin before handing sources to the drafting stage.

flowchart TD Q["Query"] --> EXP["Query expansion (HyDE / multi-query / decompose)"] EXP --> D["Dense — text-embedding-3-large"] EXP --> S["Sparse — BM25 (fastembed Qdrant/bm25)"] D --> RRF["Qdrant RRF fusion (k=60)"] S --> RRF RRF --> DEN["Concept-density select (score = 0.6·concept_count_norm + 0.4·rrf_norm)"] DEN --> SEC["Section-chunk expand (scroll all chunks of top_sections=4)"] SEC --> ADJ["Sibling-section expansion (page-band ±25, rerank-gated)"] ADJ --> RR["Cross-encoder rerank (BAAI/bge-reranker-v2-m3, top_n=10)"] RR --> DIV["Author-diversity round-robin (_DIVERSITY_MAX=6, target auto)"] DIV --> OUT["Selected sources (final_top_n=8)"]

RetrievalFlags surface

The RetrievalFlags object (threaded from the chat request through to the retrieval call) controls query-time behavior. The three query-expansion strategies — HyDE (generate a 3-sentence hypothetical passage, embed that instead of the raw question), multi-query (N LLM-generated paraphrases, each retrieved independently then RRF-merged), and decompose (2-4 sub-questions via the chained planner) — are each opt-in flags. The adjacent_sections flag activates _expand_adjacent() on the hybrid_search primitive (same-section chunk scroll, appended at score 0.001). All flags default to off for the standalone retrieval CLI; the deep-tutor pipeline activates multi-query and adjacent expansion by default.

Rationale & invariants

Why two entrypoints

The standalone service (src/services/retrieval/) exists as a LangChain-based CLI convenience, purpose-built for ad-hoc exploration and offline testing. It wraps a single named collection (settings.qdrant_collection_text) and delegates chain orchestration to LangChain abstractions. It was built first, as a thin proof of concept.

The in-process chat retrievers (src/services/chat/retrieval.py + retrievers/) exist because the deep-tutor pipeline outgrew what a LangChain retriever abstraction can express efficiently. They have no LangChain dependency, iterate all per-field collections in parallel, and add four stages that the standalone service does not have: concept-density scoring, sibling/adjacent expansion, cross-encoder reranking, and author-diversity round-robin. Keeping them in-process (not behind an HTTP call) avoids serialization overhead and lets the pipeline pass rich Python objects (scored sections with metadata) between stages without encoding/decoding.

Why density-before-rerank

RRF fusion produces a broad candidate pool ranked by lexical + semantic overlap but blind to whether a section actually contains the target concept. The density stage re-scores using a concept-term frequency count (TUTOR_DENSITY_ALPHA=0.6 weight), which pushes dense-definition sections to the top before the cross-encoder sees them. This matters because the cross-encoder is expensive (sentence-transformers, CPU) and operates on a hard cap of 50 candidates (rerank_top_k_in). If density were skipped, the reranker would waste its budget on off-topic high-RRF chunks.

Why sibling chunks are admitted at near-zero score

Sibling sections are appended at score 0.0005 — well below any real RRF score. This is intentional: the score signals to the cross-encoder that these are low-confidence candidates. The cross-encoder then assigns them a real relevance score from scratch, and only those that pass the final_top_n cut survive. Near-zero admission means the reranker is the only gate — there is no tuned threshold to maintain, and the behavior degrades gracefully: a sibling that the reranker considers irrelevant simply falls out of the top-N without any special handling.

Relevant invariants (from docs/system/invariants.md)

  • Invariant 20 — Adjacent-section expansion (density._fetch_neighbor_chunks, gated TUTOR_NEIGHBOR_EXPAND=1) is rerank-gated + sibling-prefiltered: neighbors are added to the candidate pool as low-score _PseudoPoints, kept only if same parent and within the page band (±25). The existing cross-encoder rerank + final_top_n cut is the sole gate — no tuned score threshold. The scroll is best-effort: any error returns [] and never blocks selection. TUTOR_DENSITY_ALPHA (0.6) is the concept-TF weight in _section_score; _DIVERSITY_MAX default 6.
  • Invariant 21 — The author-diversity target is honored end-to-end, not just at the round-robin: _density_select scales the section budget to eff_sections = max(top_sections, target_authors) AND applies an author-aware rerank floor — after the cross-encoder cut (widened to max(final_top_n, target_authors)), the best dropped chunk of each missing author is re-inserted. Without all three (cap ≥ N, section budget expansion, rerank floor) a chosen N silently collapses to ~3.
