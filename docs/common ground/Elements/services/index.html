statrag — Services

The architecture layers behind statrag — each a package with one responsibility and a strict import rule. 5 layers · Chinese wall

All services

ServiceLayerPathWhat it does
CoreCore · shared infrasrc/core/The shared system layer: configuration and the Qdrant client/store wrapper. Everything else depends on core; core depends on nothing in-repo.
IngestionTask · external-input → DBsrc/ingestion/One-off pipeline that turns an OCR'd book into enriched, embedded Qdrant points. Reads per-book YAML + preprocessor output, writes the field_textbooks / field_images collections.
RetrievalService · DB → resultssrc/services/retrieval/Hybrid query service: dense + sparse BM25 over the per-field collections, fused with Reciprocal Rank Fusion, optional cross-encoder rerank. The retrieval primitive every chat mode builds on.
ChatService · user-facingsrc/services/chat/The SSE-streaming conversational layer: a FastAPI app exposing the four chat modes over hybrid retrieval, including the deep-tutor pipeline (query planning → coverage → orchestrator-workers → vision).
EvalService · placeholdersrc/services/eval/Evaluation scaffolding — dataset building, generation, and metrics for retrieval / answer quality. Present but a placeholder; not wired into the live app.

Each layer page is a deep-dive: sequence + dataflow diagrams, per-module breakdown, schemas/contracts, and the invariants that govern it. Source of truth: each package __init__.py (import rules) + module listings. Click a service for its modules + entrypoint.

The Chinese wall

Core imports nothing in-repo. Tasks (ingestion) and Services (retrieval, chat, eval) import only core — never each other, never ingestion. Encoded in every __init__.py.
