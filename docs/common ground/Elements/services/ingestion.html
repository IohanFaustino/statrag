Per-module deep-dive

pipeline.py — orchestrator and CLI

The top-level orchestrator. Its public API is one function: run_chapter(book_slug, chapter_id, *, provider, force, limit_sections) (line 169). This function loads the per-book YAML, computes a chapter hash via manifest.text_hash(), checks manifest.should_skip() (skips unless --force), then sequences stages B–F in order. It returns a stats dict (keys: status, sections, chunks, split_sections, oversize, token_histogram, images) so notebooks can inspect the run without parsing logs.

The two persist helpers — _persist_text() (line 90) and _persist_images() (line 128) — are module-private. Each calls ensure_text_collection() / ensure_image_collection() from src.core.qdrant_store (idempotent create-if-absent) before upsert. _persist_images() uses a hard batch cap of BATCH = 100 points (line 151) to avoid Qdrant write timeouts on large figure sets (600+ images in some books).

Chunk IDs are UUID5 over "c::{chunk_id}" (_uuid_for(), line 86); image IDs are UUID5 over "img::{book_slug}::{image_name}". Both are deterministic — re-ingesting the same content produces the same Qdrant point IDs, so upsert is idempotent.

CLI flags (main(), line 271): --status calls cmd_status() (line 261), which prints a summary from manifest.list_books(); --provider openai|deepseek (default: settings.default_provider); --force bypasses the chapter-hash skip check; --limit-sections N truncates sections before enrichment and suppresses the manifest write (invariant 7).

build_documents.py — Stage D chunker

Implements single-tier, token-aware chunking. Module docstring (line 1–13) states the rules: one section = one chunk when the section fits within TARGET_TOKENS; if it exceeds that limit it is split into N windows of TARGET_TOKENS with OVERLAP_TOKENS overlap.

Constants (lines 29–31):

  • TARGET_TOKENS = 8000 — split threshold and window size.
  • OVERLAP_TOKENS = 200 — token overlap between consecutive windows.
  • HARD_MAX_TOKENS = 8190 — safety cap; any chunk above this logs an ERROR and increments BuildStats.n_oversize. Must be 0 after a clean ingest (invariant 6). The OpenAI embedding API hard limit is 8191 tokens.

The encoder is tiktoken.get_encoding("cl100k_base") (line 28), matching the text-embedding-3-large / GPT-4 family tokenizer. count_tokens() (line 34) passes disallowed_special=() so literal tokens like <|endoftext|> in NLP textbooks encode as normal characters rather than raising.

_flat_meta(s, book) (line 60) assembles the Qdrant payload dict from a SectionMetadata and BookMetadata. Key fields: book, book_slug, book_name, theme, authors, chapter_id, section_id, h1, h2_path, page_from, page_to, has_formula, has_image, has_table, n_formulas, synopsis (capped at 500 chars), index_extended (first 20, comma-joined). Two additional fields are added per chunk: chunk_index and n_chunks_in_section and token_count.

Deduplication: build() (line 95) de-duplicates chunk IDs before returning — content-addressable IDs (MD5 of text, line 56) make re-ingestion the same chapter idempotent; the Qdrant upsert overwrites existing points with identical IDs.

BuildStats (dataclass, line 82): fields n_sections, n_chunks, n_oversize, split_sections, token_min, token_max, token_mean, token_histogram (six buckets: <1k, 1k-2k, 2k-4k, 4k-6k, 6k-8k, >8k), per_section. Serialized to data/parsed/<book>/<chapter>_build_stats.json after every run.

llm_enrich.py + llm_client.py — Stage C enrichment

llm_enrich.py adds two metadata fields to each SectionMetadata: index_extended (5–15 extra lowercase keywords) and synopsis (1–3 sentence structured summary referencing formulas, figures, and tables by ID). The enrichment prompt (SYSTEM + USER, lines 32–65) uses a one-shot JSON example and four strict rules. Rule 1 is "synopsis MUST be a single string, NEVER an array" — enforced defensively in _coerce_synopsis() (line 88), which joins a list if the model drifts (invariant 8).

Caching (line 75): results are persisted to data/parsed/<book>/cache/<section_id>__<provider>__<hash>.json. The hash is MD5(text + "|" + formulas) (line 81), so re-ingesting unchanged sections uses zero LLM tokens. The cache is NOT cleared by --force; to force re-enrichment, delete the cache directory.

llm_client.py (line 25, get_llm()) returns a langchain_openai.ChatOpenAI instance wired to the chosen provider:

  • openai → settings.openai_model_nano (gpt-5.4-nano-2026-03-17).
  • deepseek (default) → settings.ingest_deepseek_model (deepseek-v4-flash, line 37) via base_url=settings.deepseek_base_url. DeepSeek v4 model IDs default to thinking mode — they spend tokens on reasoning_content and may return empty content, which breaks JsonOutputParser. Thinking is disabled explicitly with extra_body={"thinking": {"type": "disabled"}} (line 41). Verified in module comment lines 33–36.

Groq is explicitly out of scope for ingestion (invariant 26 in docs/system/invariants.md); get_llm() only accepts "openai" or "deepseek" (the Provider Literal, line 22).

regex_pass.py — Stage B section parser

A deterministic, streaming line-by-line parser over a markdown chapter slice. It emits one SectionMetadata per H2+ section. The key design choices:

  • Page-state tracking: every <!-- page N --> comment updates current_page (line 186). A look-behind scan (_peek_page_before(), line 63) initialises the page cursor from lines before the chapter slice, so the first section's page_from is never None (invariant 2).
  • H2-path hierarchy: numbered headers (e.g. "2.1", "2.1.1") form the backbone stack; unnumbered headers are leaf sub-sections appended to the last numbered ancestor. The path separator is " | " (invariant 9). Levels are determined by _numeric_depth() (line 93) which counts ./- separators in the numeric prefix.
  • OCR noise filter: RE_OCR_HEADER_NOISE (line 32) drops headers that are Python REPL output (Out[, In[, >>>) wrongly marked up as headers. OCR page-header bleed ("### N. Statistical Learning") is stripped before parsing via _strip_ocr_bleed() (line 135).
  • Artifact extraction: _extract_artifacts() (line 112) collects block formulas ($$…$$), inline formulas ($…$), image refs (<img src="imgs/…"> and ![](imgs/…)), HTML tables, and TABLE reference strings into the SectionMetadata lists.
  • H1 default: chapter_title from the per-book YAML seeds current_h1 (line 146) so even chapters without an explicit # header get a non-empty h1 (invariant 4).

extract_images() (line 249) performs a second pass over the parsed sections using RE_IMG_AND_CAPTION (line 47) to pair each figure with its nearest <div>FIGURE X.Y…</div> caption. Unpaired images are matched to orphan captions; images without any caption are assigned "(no caption found)".

ingest_images_only.py — standalone image ingest

A separate CLI (python -m src.ingestion.ingest_images_only --book <slug> --md <path>) for VLM-processed or EPUB-converted markdown that has rich figure content but whose text side has already been ingested (or does not use the standard chapter-slice format). It skips the text pipeline entirely.

Two extraction paths are available, selected by --format vlm|epub|auto (default auto, which inspects the first image reference pattern):

  • VLM format (extract_vlm_images(), line 248): image refs look like ![](images/<sha>.jpg). Captions are assembled from preceding prose and the nearest <details><summary>…</summary>…</details> block (VLM dump output format).
  • EPUB format (extract_epub_images(), line 188): refs are ![alt](markdown/<Title>/media/…/*.jpg); captions come from the next italicized single-line paragraph (*Figure x.x: …*). Inline-math art files (Art_P*.jpg) are skipped.

Both paths call _is_cover_image() (line 61) to drop title-page / cover / endpaper images (filename hint or position in first 3% of file with no preceding prose). After extraction the standard _persist_images() from pipeline.py is called (imported at line 25). A ManifestEntry with chapter_id="images_only" and chunk_count=0 is written (invariant 15). The --dry-run flag logs 3 sample records without upserting.

manifest.py — Stage F registry

Maintains data/parsed/manifest.json — a flat JSON list of ManifestEntry records, one per (book, chapter) pair. The manifest is the idempotency gate: should_skip() (line 54) returns (True, reason) when the (book_slug, chapter_id) pair exists with the same chapter_hash and status="success". If the chapter content changes (new OCR correction, section addition), the hash differs and re-ingest proceeds.

register() (line 70) is upsert-style: it removes the previous entry for the same (book, chapter) pair and appends the new one. The file is loaded and saved in full on each call — acceptable because manifest files are small (tens of entries).

Hash functions: file_hash(path) (line 27) — MD5 over the full source file; text_hash(text) (line 36) — MD5 of the chapter slice text string. Both return "md5:<hex>". list_books() (line 86) returns summary dicts for the CLI --status output.

schema.py — Pydantic models

All Pydantic models for the ingestion layer are defined here (line 1, module docstring: "Mirrors ingestion/reference.md schema"). There are four classes: BookMetadata, SectionMetadata, ImageMetadata, and ManifestEntry / Manifest. See the Schemas & contracts section below for field details.

Schemas & contracts

Chunk-record payload (text collection)

Each Qdrant point in <field>_textbooks has a payload assembled by _flat_meta() (build_documents.py line 60) plus three per-chunk fields added in the loop (line 119): chunk_index, n_chunks_in_section, token_count. The full field-by-field reference (including invariant notes for book / book_slug / book_name triad, page_from > 0, synopsis string, theme) lives in Ingestion → Chunking.

Invariant check: book == book_slug != book_name (invariant 1); page_from > 0 for the first section (invariant 2); synopsis is always str, never a list (invariant 5); token_count ≤ 8190 (invariant 6); theme non-empty (invariant 11).

Rationale & invariants

Why ingestion is a task, not a service

A task in this codebase is a one-off, offline process that reads external inputs (OCR'd markdown, per-book YAML, preprocessor scripts) and writes to the database. It has no request path, no server, and no users connecting to it at runtime. The pipeline runs once per chapter, is gated by a content hash, and is intentionally separate from all user-facing services.

This matters for the import wall: the Services layer (chat, retrieval, eval) must be able to start up, handle requests, and re-deploy without touching or even importing any ingestion code. Ingestion is an upstream artifact producer; services are downstream artifact consumers. Services read the ingestion artifacts as files — src/ingestion/books/<slug>.yaml, data/parsed/manifest.json, the Qdrant collections — and import ONLY src.core. They never import src.ingestion.*.

Conversely, src/ingestion/ imports only src.core + third-party libraries. This is enforced by the module docstring in __init__.py (lines 1–7) and is checked visually in every pipeline module's import block. Violating the wall (e.g. importing from src.services.chat) would create a circular dependency that Python would surface immediately at startup.

Relevant invariants from docs/system/invariants.md

  • Invariant 3 — One section ≈ one chunk; multi-chunk only when section exceeds 8000 tokens. BuildStats.split_sections must equal the count of sections over that threshold.
  • Invariant 6 — n_oversize == 0 after every ingest. Any chunk above HARD_MAX_TOKENS = 8190 would be silently truncated by the OpenAI embedding API.
  • Invariant 7 — --limit-sections N MUST NOT write the manifest. Pre/post manifest.list_books() length must be unchanged on a preview run.
  • Invariant 15 — Image-only ingest writes a ManifestEntry with chapter_id="images_only", chunk_count=0, image_count=N.
  • Invariant 16 — Image collections must exist before any tutor query routes there; ensure_image_collection runs inside _persist_images (auto-creates). Upserts are chunked at ≤ 100 points per batch.
