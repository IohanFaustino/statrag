Per-module deep-dive

src/services/eval/ — scaffold package

All four modules exist and contain real code — they are not empty stubs — but the package as a whole is not integrated into the live app or a stable CLI workflow. The __init__.py wall comment says "invokes the chat service via HTTP (not direct module import) to preserve the Chinese wall". The runner is designed for an offline batch run against a live backend URL.

Module Status Role
dataset.py Scaffold — complete Defines QARecord (Pydantic model: id, q, gold_book, gold_chapter, gold_section, gold_chunk_id, gold_answer, tags). Provides load() / save() for JSONL files. No placeholder methods — this module is functional.
generator.py Scaffold — complete Generates synthetic Q/A pairs by sampling data/parsed/manifest.json, scrolling Qdrant for a real chunk, and calling OpenAI nano to produce a question + reference answer. CLI: python -m src.services.eval.generator --n 50 --out data/eval/base50.jsonl. Not part of normal dev workflow — requires live Qdrant + API key.
metrics.py Scaffold — complete Four metrics: context_precision (deterministic, fraction of retrieved chunks matching gold), context_recall (binary gold-in-set check), faithfulness (async LLM judge: unsupported-claims ratio), answer_relevance (async LLM judge: 0–1 relevance score). All use the nano model as judge. See Schemas section for definitions.
runner.py Scaffold — complete Async CLI orchestrator: loads a JSONL set, POSTs each question to the chat backend SSE endpoint, computes all four metrics, writes a timestamped JSON report to data/eval/reports/, and performs a regression gate (5% drop triggers exit code 1). CLI: python -m src.services.eval.runner --set base50 --mode tutor --backend http://localhost:8765. Not run in CI or the default dev workflow.

src/services/chat/eval/ — live feature-specific harnesses

These are standalone scripts that live next to the chat-service code they test. They import directly from src.services.chat.* (eval-only use — not violating the wall in the sense that they are scripts, not library modules). Each is run manually with pytest markers or python -m as needed; none runs in the default regression lane. Results are written to docs/superpowers/eval/ as markdown artifacts.

File Role
facilitate_eval.py Offline LLM-judge eval for the facilitate teach node. Runs two prompt variants (shipped v1 vs stricter v2) against hansen ch07 sections 7.1–7.4, judges each on 5 dimensions (clarity, faithfulness, keypoint_coverage, non_expansion, concept_id), 3 runs each, writes ranked markdown table. Marker: facilitate_eval.
facilitate_reasoning_eval.py A/B eval: facilitate map+teach with hidden CoT reasoning scratchpad vs without. Swaps prompts/schemas locally — does not modify the shipped pipeline. Marker: facilitate_reasoning.
ow_harness_compare.py Orchestrator-workers harness ablation (Plan A baseline). Freezes multi-author sources for 3 cross-book questions, runs the workflow at levels L0 / L2 / L3, judges each answer on faithfulness / coverage / synthesis / coherence (1–5). Step-based CLI: --step freeze | run | judge.
ow_deepagents_compare.py Plan C: 4-arm deepagents synthesizer comparison — L0 (current), L3a (bare deepagents), L3b (deepagents + synthesis skill), L4 (deepagents + per-author subagents). 6 questions × 3 runs/arm, full-text judge, real token + cost capture. Requires pip install deepagents.
planner_chain_compare.py Ablation for the query-planner chain across nano / gemini-2.5-flash / qwen-plus. Judges the produced plan on decomposition / coverage / targeting / redundancy. No Qdrant required. Step-based CLI.
structured_synth_compare.py Lightweight A/B/C comparison for the structured-synth cycle (harness levels 5 / 6 / 7). Scores clean-math violations, component-formula presence, bullet density, latency, and tokens. Provides pure helper functions (count_clean_math_violations, has_component_formulas, count_bullets) importable for other scripts.
ts_components_compare.py 5-contestant offline eval: "what are the components of a time series?" fed the same frozen RAG context. API contestants (nano, gemini, qwen) called here; Claude agents (sonnet, opus) dispatched by the orchestrator and written to the same work directory. Step-based CLI: retrieve → api → judge.

Schemas & contracts

Eval dataset schema — QARecord

Defined in dataset.py. Each record is a Pydantic model persisted as a JSONL line.

FieldTypeDescription
idstrStable 8-char UUID prefix
qstrQuestion text
gold_bookstrExpected book slug (e.g. hansen)
gold_chapterstrExpected chapter id (e.g. ch06)
gold_sectionstrh2_path or last-segment label
gold_chunk_idstr | NoneAuthoritative Qdrant point UUID (optional)
gold_answerstr2–3 sentence reference answer
tagslist[str]Mode-relevance tags, e.g. ["tutor"]

Default dataset path: data/eval/base50.jsonl. Reports written to data/eval/reports/. Baselines stored at data/eval/baselines.json.

Retrieval + answer metrics — metrics.py

MetricTypeDefinition
context_precision Deterministic, synchronous Fraction of retrieved chunks whose chunkId matches gold_chunk_id. Returns 1.0 when no gold id is set (permissive). Range [0, 1].
context_recall Deterministic, synchronous 1.0 if the gold chunk appears anywhere in the retrieved set, else 0.0. Binary. Returns 1.0 when no gold id (permissive).
faithfulness LLM-judge, async Prompts nano model to count total claims in the answer and how many are unsupported by the top-5 retrieved texts. Score = 1 − (unsupported / total). Range [0, 1].
answer_relevance LLM-judge, async Prompts nano model to score 0.0–1.0 how well the answer addresses the original question. Clamped to [0, 1].

Runner aggregates produce context_precision_at_10, context_recall, faithfulness, and answer_relevance means, and compare against a per-mode baseline with a 5% regression gate.

Image-judge KPIs — pytest -m quality_images

Sourced from docs/eval/image_label_instructions.md. A human-labelled CSV (~32 rows, 8 seed queries × 4 image candidates) provides ground truth with two columns: label_include (0/1) and label_aspect (one of: tldr, definition, formal_statement, intuition, examples, trade_offs, further_reading).

MetricTarget
Precision (include verdict)≥ 0.80
Recall (include verdict)≥ 0.70
F1≥ 0.74

Latency overhead< 2 000 ms median

KPIs sourced verbatim from docs/eval/image_label_instructions.md §4. Tuning knobs: TUTOR_DEEP_TIER1_INCLUDE / TUTOR_DEEP_TIER1_EXCLUDE thresholds in agents/deep_tutor.py. Runner: .venv/bin/pytest -m quality_images src/services/chat/tests/test_image_judge_quality.py -s. The default pytest src/services/chat/tests/ lane deselects the marker so the live API and label CSV are never required for normal regression.

Rationale & invariants

Why eval is split across two surfaces

The src/services/eval/ package was designed as a future generic harness that can evaluate any chat mode end-to-end over HTTP — without importing chat internals. That design is correct and the code is complete, but it has not yet been wired into a scheduled CI lane or an operational workflow. No eval set file (data/eval/base50.jsonl) has been generated yet in the current deployment; the generator requires a live Qdrant + OpenAI API call.

Meanwhile, as each chat-service feature was built and ablated, lightweight eval scripts naturally grew next to the code they test, under src/services/chat/eval/. These scripts are intentionally not generic — each is purpose-built for a single pipeline stage or model variant. They write their artifacts to docs/superpowers/eval/ for review. The benefit of co-location is that a developer can run python -m src.services.chat.eval.ow_harness_compare --step run immediately after changing the orchestrator-workers stage, without populating any central dataset first.

The pytest -m quality_images lane occupies a middle ground: it uses a human-labelled ground-truth CSV (a lightweight offline process) and is opt-in rather than part of the default regression run. This keeps CI fast while still providing a repeatable precision/recall gate for the image judge.

Invariants

No numbered invariant in docs/system/invariants.md is specifically dedicated to the eval surface. The relevant operative rule is the Chinese-wall import constraint: src/services/eval/ may only import src.core.* and must invoke the chat service over HTTP, never via direct module import. This is documented in src/services/eval/__init__.py and runner.py enforces it by using httpx against a configurable backend URL.

The image-label guide lives at docs/eval/image_label_instructions.md. Generate the label CSV with ops/scripts/build_image_label_set.py --out data/eval/image_label_set.csv before running the quality_images marker.
