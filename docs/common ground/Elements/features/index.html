Features user-facing

What users actually invoke — four chat modes over one hybrid-retrieval core.

A feature in statrag is a capability the user directly invokes: pick a mode, ask a question (or name a chapter), and the system delivers a structured response. Each mode is a distinct teaching contract — different output shape, different depth, different pipeline — but all of them run on the same hybrid retrieval foundation and the same Qdrant collections.

The deep-tutor pipeline is the engine beneath the two search modes (Tutor and Q&A). The chapter modes (Facilitate and Resume) share the same retrieval stack but follow a structural fetch path instead of a question-driven search.

Four chat modes

Tutor

The default, deepest mode. Answers a question with a multi-author, structured tutorial: TL;DR, definition, formal statement, worked example + intuition, applications, and further reading — with inline citations, figures, and rendered math.

single-agent

Q&A

Punctual, scoped Q&A. Extracts the precise gap the question asks about (and what it assumes you already know), retrieves a small high-precision set, generates a terse grounded answer, then verifies that every claim is supported.

multi-agent

Facilitate

An ordered, didactic walkthrough of a whole chapter. Fetches the chapter's sections in the book's own order and teaches each one (verbose map, ~250-400 tokens/section), streaming each block as it finishes so you watch the chapter build top to bottom.

chapter pipeline

Resume

An ordered, compressed recap of a whole chapter. Same structural pipeline as Facilitate, but the map step is terse (~60-100 tokens/section) — a faithful condensed summary in reading order.

chapter pipeline

The deep-tutor pipeline

When Tutor mode runs, it executes a multi-stage agentic pipeline: a query planner decomposes the question into concepts, sub-queries, and facets; multi-query retrieval fans out against Qdrant and merges results with Reciprocal Rank Fusion; a density + rerank stage applies cross-encoder scoring and author-diversity filtering so no single textbook dominates; a coverage loop checks whether every facet is represented and re-retrieves for gaps; a figure judge selects the most relevant images; the planner-orchestrator builds a synthesis plan; orchestrator-workers draft per-author sections in parallel, with formula recovery for any OCR-dropped equations; and finally vision-explain annotates figure captions before the assembled DeepTutorAnswer is streamed back. Q&A runs a lighter 4-node graph variant of the same core.

Powered by retrieval

Every mode runs on the same hybrid retrieval stack: dense embeddings (OpenAI text-embedding-3-large, 3072d) fused with sparse BM25 via Reciprocal Rank Fusion, with an optional cross-encoder rerank pass and author-diversity filtering applied on top. The collections are partitioned by field (field_textbooks for sections, field_images for figures) so queries stay within the correct subject area. For the full mechanics, see the retrieval deep-dive.
