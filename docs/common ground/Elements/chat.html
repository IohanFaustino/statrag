Drift notes vs hint diagram: (1) The hint diagram showed a single "Multi-query retrieval" node. The code runs two parallel tasks: extract_concepts_ex (query planner) and _wide_candidates (raw-query anchor) — both launch simultaneously before the planner result is known. (2) Hint showed one Coverage loop-back edge; the code skips coverage for "simple" questions (perspectives <= 1, < 4 facets, no formula facet) — so the loop has an implicit gate. (3) The hint labelled "Planner-Orchestrator" as one node; the code separates the synthesis plan step (which feeds all workflows) from the per-workflow drafting. (4) tutorPipeline.ts says vision_explain is "on by default" but code default is "lazy" (TUTOR_DEEP_VISION_EXPLAIN=lazy) — off unless explicitly set to "1". This is a drift between the modal card label and the actual default.

Streaming — SSE & resumable runs

SSE endpoints in src/services/chat/api.py. Run manager in src/services/chat/runs.py.

RouteMethodPurpose
/api/chat POST Start (or attach to) a chat turn. With conversationId: launches a detached resumable run via runs.start_run(); generation survives client disconnect. Without conversationId: ephemeral connection-bound stream (legacy path).
/api/chat/{conv_id}/stream GET Resume an in-flight or finished run, replaying events after ?after=N (monotonic seq). Returns an immediately-closing stream when no run exists for the conversation.
/api/chat/{conv_id}/status GET Resume handshake: returns {exists, active, done, seq}. Used by the client before subscribing to decide whether to replay or fetch persisted transcript.
/api/models GET Returns full provider/model registry (list of ModelProvider). Used by the picker UI.
/api/health GET Liveness probe — always 200 if process is up.
/api/figures GET Serve a figure image. Path must resolve under a whitelisted root and have an image extension. Prevents path traversal.

Resumable run invariants

  • Monotonic seq: every buffered event gets a strictly increasing integer seq (1-based), injected by the run driver. The SSE id field is set to seq for native EventSource reconnection. (runs.py:99–105)
  • At most 1 active run / conversation: start_run() returns the in-flight run if one already exists — never starts a duplicate. (runs.py:145–151)
  • Run persists with zero subscribers: the background asyncio.Task drains to completion regardless of subscriber count; the assistant row is persisted on completion. (runs.py:92–111)
  • TTL GC: finished runs are garbage-collected after 300 s (RUN_TTL_SECONDS). Late subscribers within that window still get full replay. (runs.py:35)
  • Restart loss: runs are process-local (in-memory); a backend restart loses an in-flight run. Persisted turns (SQLite) survive. (runs.py:19–20)

SSE event types (in order)

Emitted by run_deep_tutor in this order: meta, token (streaming, repeated), structured_output (schema=TutorAnswer), sources_full, figures_full, figures_meta, retrieval_meta, usage, done. On error: error + done.
